# Установка llm-wiki-tags (инструкция для агента)

> # llm-wiki-tags — ЭТО ТОТ ЖЕ **llm-wiki** ОТ АНДРЕЯ КАРПАТОГО, НО С **ТЭГАМИ**.

*Языки: [English](INSTRUCTIONS.md) · **Русский** — Описание:
[English](README.md) · [Русский](README.ru.md)*

Ты — ИИ-агент для кода. Пользователь попросил **установить llm-wiki-tags** в
текущий репозиторий. Выполни шаги ниже, адаптируя пути и синтаксис комментариев
под репозиторий. Не перестраивай и не переписывай существующий контент сверх
того, что нужно для соблюдения правил. Вноси изменения как обычную правку
репозитория.

## Концепт

Держи документацию как читаемую LLM вики (llm-wiki —
[оригинальный gist Андрея Карпатого](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f))
и добавь **тэги**, которые связывают код и документацию поперёк дерева директорий.

**Тэг** — короткий slug в kebab-case (`[a-z0-9-]+`, иерархический через `/`),
записанный токеном `@tag:<slug>`. **Один и тот же тэг ставится и в коде, и в
документации**, чтобы концепт, охватывающий несколько файлов/папок, находился
одним поиском.

Соглашение поставляется **файлами правил**. Сначала ты ставишь их в репозиторий
(шаг 1), а потом применяешь: правила — каноническая формулировка, эта страница —
только процедура.

## Шаги

### 1. Установи файлы правил

Скопируй файлы из [`rules/`](rules/index.ru.md) в
`.claude/rules/llm-wiki-tags/` **дословно**, не пересказывая. Claude Code
подгружает каждый `.md` из `.claude/rules/` на каждой задаче — именно это делает
соглашение устойчивым. Забрать файлы можно по
`https://raw.githubusercontent.com/mpashka/llm-wiki-tags/main/rules/<файл>`.

Всегда:

| Источник | Ставится как |
| --- | --- |
| `rules/wiki.ru.md` | `.claude/rules/llm-wiki-tags/wiki.md` |
| `rules/docs-layout.ru.md` | `.claude/rules/llm-wiki-tags/docs-layout.md` |
| `rules/tags.ru.md` | `.claude/rules/llm-wiki-tags/tags.md` |
| `rules/glossary.ru.md` | `.claude/rules/llm-wiki-tags/glossary.md` |

Плюс по одному `code-tags-<язык>.md` на каждый язык, который в репозитории
действительно есть, — `rules/code-tags-java.ru.md`, `code-tags-python.ru.md`,
`code-tags-golang.ru.md` — и ни одного для отсутствующих языков. У каждого во
front matter есть поле `paths:`, поэтому файл подгружается, только когда трогают
код на этом языке.

- **Язык правил**: у каждого файла есть пара `.md` (английская) и `.ru.md`.
  Ставь ту, что совпадает с языком документации репозитория, убирая `.ru` из
  имени устанавливаемого файла.
- **Язык, для которого готового файла нет**: напиши его по тому же образцу на
  основе [`languages/`](languages/index.ru.md), с правильным glob'ом в `paths:`
  (`paths: "**/*.ts, **/*.tsx"` — список или строка через запятую).
- **Адаптируй после копирования, а не вместо него**: если директория документации
  в репозитории не `docs/` или какое-то правило действительно не подходит —
  правь уже установленный файл и скажи об этом в отчёте.

Дальше прочитай то, что установил, и применяй по шагам ниже.

### 2. Разложи документацию — `docs-layout.md`

Создай дерево `docs/`: `specification/` (взгляд снаружи), `implementation/`
(взгляд внутрь), `testing/`, `requests/` (рабочие файлы задач). Перенеси в него
разрозненные документы из корня репозитория, поправив ссылки; оставляй страницу в
корне, только если этого требуют инструменты или внешняя ссылка. Если в
репозитории уже есть своя директория документации — сохрани её имя.

### 3. Построй дерево `index.md` — `wiki.md`

Убедись, что в каждой значимой директории — и в `docs/`, и в дереве кода — есть
`index.md` с однострочным описанием каждого файла и поддиректории, со ссылками на
родительский индекс и дочерние индексы. Создай недостающие.

### 4. Создай реестр тэгов — `tags.md`

Создай `docs/tags.md`: все тэги с однострочным описанием связываемого концепта,
разложенные иерархически, плюс формат тэга и команды поиска (скопируй разделы
«Формат тэга» и «Поиск» из [`README.ru.md`](README.ru.md)). Добавь его в
`docs/index.md`.

### 5. Заведи словарь терминов — `glossary.md`

Создай `docs/terms.md` и добавь его в `docs/index.md`. Наполни его терминами
предметной области, которые уже повторяются в коде и документации, — имена
классов и модулей, слова существующих страниц: у каждого основной термин,
синонимы в ходу и определение в одну строку. Если у одного понятия два имени,
основным бери то, что уже в коде, а второе запиши синонимом; код на этом шаге не
переименовывай. Терминов, которых в репозитории нет, не выдумывай.

### 6. Расставь тэги — `tags.md`, `code-tags-<язык>.md`

Для каждого концепта, который охватывает **и код, и документацию**: выбери slug,
зарегистрируй его в `docs/tags.md`, затем поставь буквальный токен `@tag:<slug>`
в документации (YAML front matter либо строкой в теле для одного раздела) и в
коде (комментарий над пакетом, файлом, классом или функцией). Иерархия —
`@tag:payments/retry` — лучше длинного плоского slug'а; тэги под разовые детали
не выдумывай.

### 7. Зафиксируй соглашение для остальных агентов

Агенты, кроме Claude Code, не читают `.claude/rules/`. В гайде для агентов
репозитория (`AGENTS.md`, иначе создай) добавь короткий раздел
**«llm-wiki-tags»**: пять-шесть строк с выжимкой установленных правил плюс ссылки
на `.claude/rules/llm-wiki-tags/`, `docs/tags.md` и `docs/terms.md`. Детали держи
в файлах правил — гайд ссылается на них, а не дублирует.

## Коротко (каноническая формулировка — в файлах правил)

- **Документация — это LLM-вики**: `index.md` в каждой значимой директории,
  двусторонние ссылки, у каждой детали одна страница-владелец.
- **Вся документация лежит в `docs/`** — `specification/`, `implementation/`,
  `testing/`, разложенные по тэгам и иерархичные, где возможно; в корне только
  те файлы, которые обязаны там быть.
- **Рабочие файлы задачи — в `docs/requests/<task_name>/`** (`request.md`,
  `plan.md`, отладочные скрипты), не в корне и не рядом с кодом.
- **Сначала читай, потом делай; обновляй по ходу.** Документация, разошедшаяся с
  кодом, — это дефект.
- **Тэгируй сквозные концепты** и держи `docs/tags.md` актуальным.
- **Одно понятие — одно слово**: прежде чем что-то назвать, ищи в `docs/terms.md`
  по смыслу; новое имя старого понятия становится синонимом.

## Готово

После установки скажи пользователю, что создал/изменил: файлы правил в
`.claude/rules/llm-wiki-tags/` (и для каких языков), раскладку `docs/`,
добавленные `index.md`, `docs/tags.md`, `docs/terms.md` с заведёнными терминами,
расставленные тэги и раздел в гайде для агентов. Дальше на каждой задаче в этом репозитории соблюдай установленные
правила.
