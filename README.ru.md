*Языки: [English](README.md) · **Русский** — Инструкция для агента:

## Что это

**llm-wiki** ([оригинальный gist Андрея Карпатого](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f))
— идея хранить документацию кодовой базы как *вики, читаемую LLM*: в каждой
значимой директории лежит `index.md`, страницы
маленькие и об одном, ссылки двусторонние (родитель ⇄ потомок), и у каждой
детали есть ровно одна страница-владелец. Агент идёт по дереву сверху вниз через
`index.md`, а не грепает вслепую.

**llm-wiki-tags** — это то же самое, **плюс тэги**: в самом llm-wiki ничего не
меняется, тэги добавляются сверху.

## Что добавляют тэги

**Тэг** — короткий slug в kebab-case, записанный токеном `@tag:<slug>`. Один и
тот же тэг ставится **и в коде, и в документации**, что создаёт явную
**связь код ⇄ документация**, не зависящую от структуры директорий. С тэгами
можно:

- **искать код и документацию по тэгу** — один поиск возвращает все файлы (код
  или документы), несущие концепт, даже если они разбросаны по дереву;
- **понять, какие тэги есть у части кода** — прочитать тэги вверху файла или
  директории и узнать, в каких сквозных концептах он участвует;
- **понять, какие тэги есть у документа** — то же самое для страницы
  документации;
- держать единый **реестр тэгов** (`docs/tags.md`) с описанием каждого тэга;
- **раскладывать документацию по тэгам** — `docs/external/`, `docs/specification/`,
  `docs/implementation/` и `docs/testing/` повторяют иерархию тэгов, так что
  страница про концепт лежит там, где говорит его тэг.

Тэги дополняют навигацию через `index.md` (которая идёт по дереву директорий)
второй, ортогональной осью: концепт, охватывающий несколько папок, достижим за
один шаг.

### Формат тэга

Slug — нижний регистр, kebab-case (`[a-z0-9-]+`), может быть **иерархическим**
через `/` (`@tag:payments/retry`); один и тот же токен `@tag:<slug>` ставится и в
коде, и в документации.

- **Документация** (`.md`): в **YAML front matter** вверху файла, поле `tags` со
  списком токенов через пробел; для директории — в её `index.md`. Тэг, относящийся
  только к одному разделу, можно вместо этого поставить строкой `@tag:<slug>` в
  теле рядом с ним.
  ```
  ---
  tags: "@tag:payments @tag:retry"
  ---
  ```
- **Код**: комментарий в синтаксисе языка с токеном, поставленный над элементом.
  Тэг может маркировать **пакет**, **файл**, **класс** (или аналог) или
  **метод/функцию**. Правила по языкам — в [`languages/`](languages/index.ru.md):
  [Java](languages/java.ru.md), [Python](languages/python.ru.md),
  [Go](languages/golang.ru.md).
- **Несколько тэгов**: повторить токен через пробел: `@tag:ui @tag:mechanism`.
- **Иерархия**: `@tag:payments/retry` — потомок `@tag:payments`; один поиск по
  родителю находит и родителя, и всех потомков. Иерархия лучше длинного плоского
  slug'а и повторяет дерево документации.

### Поиск

```bash
# все места (код + документация), где стоит тэг (и его потомки)
grep -rn "@tag:payments" .

# какие тэги есть у конкретного файла
grep -oE "@tag:[a-z0-9/-]+" path/to/file

# все тэги, используемые в репозитории
grep -rhoE "@tag:[a-z0-9/-]+" . | sort -u
```

Каждый тэг один раз регистрируется в `docs/tags.md` с однострочным описанием.

## Правила index.md

llm-wiki-tags сохраняет (и делает явными) правила документации из llm-wiki:

1. **В каждой значимой директории есть `index.md`** с **однострочным описанием
   каждого файла и каждой поддиректории** этой папки.
2. Индексы описывают стабильные концепты, а не список изменений. Много маленьких
   страниц лучше одной большой; локальные детали — рядом с кодом, который они
   описывают.
3. **Двусторонняя навигация**: родительские индексы ссылаются на дочерние
   страницы; дочерние — обратно на родительский индекс и на связанные страницы.
4. **У детали одна страница-владелец**; остальные ссылаются на неё — не
   дублировать.
5. **Сначала читай, потом делай**: перед задачей пройди по `index.md` от
   ближайшей директории вниз до кода, который будешь менять.
6. **Обновляй по ходу**: во время или после задачи обнови затронутые `index.md`
   (и тэги) в том же изменении.

## Раскладка документации

llm-wiki-tags задаёт ещё и **где** лежат страницы, чтобы и человек, и агент
угадывали путь к странице по концепту, который она описывает:

```
docs/
├── index.md                      # индекс документации
├── tags.md                       # реестр тэгов
├── terms.md                      # словарь терминов: одно понятие — одно слово
├── external/                     # система вокруг программы: архитектура, соседи
├── specification/                # как программа выглядит снаружи
│   ├── index.md
│   ├── payments.md               # небольшая область: одна страница
│   └── payments/                 # разросшаяся область: директория со своим index.md
│       ├── index.md
│       └── retry.md
├── implementation/               # как она устроена внутри — та же форма
├── testing/                      # как тестируется: среды, подходы, тест-кейсы
└── requests/                     # рабочие файлы отдельных задач
    └── <task_name>/              # request.md, plan.md, отладочные скрипты, заметки
```

- **Вся документация лежит в `docs/`.** В корне репозитория остаётся только то,
  что обязано там быть: `AGENTS.md`, `CLAUDE.md`, readme, лицензия и файлы,
  которые инструменты требуют в корне (`package.json`, `go.mod`, `Makefile`,
  конфиг CI…).
- **Четыре взгляда, страница ровно в одном**: `external/` — система вокруг
  программы и внешняя архитектура; `specification/` — взгляд снаружи;
  `implementation/` — взгляд внутрь; `testing/` — где и как это тестируется:
  среды, подходы, краткие тест-кейсы.
- **Внешняя архитектура рисуется раньше внутренней**: компоненты или
  развёртывание и сквозные последовательности — в `external/`, варианты
  использования — в `specification/`, классы, состояния и внутренние
  последовательности — в `implementation/`.
- **Разложено по тэгам, иерархически**: `@tag:payments/retry` ↔
  `docs/implementation/payments/retry.md`. Называть файл по тэгу предпочтительно,
  но не обязательно: используй тэг в имени, когда он — основная тема страницы; у
  страницы обычно несколько тэгов во front matter.
- **Рабочие файлы задачи — в `docs/requests/<task_name>/`**: постановка, план,
  отладочные скрипты. То, что переживает задачу, тем же изменением уезжает в
  `external/`, `specification/`, `implementation/` или `testing/`; папка задачи остаётся
  историей.
- **Одно понятие — одно слово**: `docs/terms.md` — словарь терминов: для каждого
  понятия основной термин, синонимы, которые он заменяет, короткое определение и
  ссылка на страницу-владельца. Новое имя вводится только после поиска по словарю
  по смыслу; новое имя старого понятия становится синонимом.

## Где лежат правила

Установка llm-wiki-tags записывает соглашение в **правила** репозитория —
`.claude/rules/llm-wiki-tags/`, которые Claude Code подгружает на каждой задаче:

```
.claude/rules/llm-wiki-tags/
├── wiki.md               # правила index.md, «сначала читай», «обновляй по ходу»
├── docs-layout.md        # дерево docs/ выше
├── tags.md               # формат тэга, реестр, команды поиска
├── glossary.md           # docs/terms.md: сначала найди, потом называй
├── code-tags-java.md     # paths: ["**/*.java"]   — грузится, только когда трогают Java
├── code-tags-python.md   # paths: ["**/*.py"]
└── code-tags-golang.md   # paths: ["**/*.go"]
```

Эти файлы поставляются готовыми в [`rules/`](rules/index.ru.md) (у каждого есть
английская и русская версия) и копируются **дословно**: устанавливающий агент не
пересказывает соглашение своими словами, поэтому во всех репозиториях оказывается
одна и та же формулировка. Файл правил с полем `paths:` во front matter
подгружается, только когда в работе подходящий файл, — правила по языкам ничего
не стоят, пока не применяются. Агентам, которые не читают `.claude/rules/`,
достаётся короткий раздел «llm-wiki-tags» в `AGENTS.md` со ссылками на эти файлы.

## Как подключить

Дайте кодовому агенту ссылку на страницу с инструкцией и попросите поставить:

```
поставь https://github.com/mpashka/llm-wiki-tags/blob/main/INSTRUCTIONS.ru.md
# или по-английски:
install https://github.com/mpashka/llm-wiki-tags/blob/main/INSTRUCTIONS.md
```

Агент читает [`INSTRUCTIONS.ru.md`](INSTRUCTIONS.ru.md) (или
[`INSTRUCTIONS.md`](INSTRUCTIONS.md)) и настраивает в текущем репозитории
раскладку `docs/`, дерево `index.md`, механизм тэгов, реестр `docs/tags.md` и
словарь `docs/terms.md`, а затем ставит соглашение как правила в `.claude/rules/llm-wiki-tags/` (плюс
ссылка в гайде для агентов), чтобы будущие агенты его соблюдали.
