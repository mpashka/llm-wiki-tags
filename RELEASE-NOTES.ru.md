# История версий

*Языки: [English](RELEASE-NOTES.md) · **Русский** — Описание:
[README.ru.md](README.ru.md) · Установка: [INSTRUCTIONS.ru.md](INSTRUCTIONS.ru.md)*

llm-wiki-tags — это соглашение, а не программа: «версия» здесь — состояние
страниц, из которых агент ставит соглашение. Чтобы перевести уже настроенный
репозиторий на новую версию, снова дайте агенту
[`INSTRUCTIONS.ru.md`](INSTRUCTIONS.ru.md) — он перекопирует файлы правил поверх
старых.

## v0.2.0

**Раскладка документации.** Теперь соглашение задаёт не только то, как
документация индексируется, но и *где* она лежит: всё в `docs/`, разделённое на
`specification/` (взгляд снаружи), `implementation/` (взгляд внутрь) и
`testing/`, разложенное по тэгам; в корне репозитория остаются только те файлы,
которые обязаны там быть.

**Рабочие файлы задач.** `docs/requests/<task_name>/` — место для постановки,
плана и отладочных скриптов, а не корень репозитория. То, что переживает задачу,
тем же изменением уезжает в постоянные страницы.

**Иерархические тэги.** Slug теперь может быть иерархическим через `/`:
`@tag:payments/retry` — потомок `@tag:payments`, один поиск по родителю находит
всех потомков, а путь тэга повторяет путь документа. Плоские slug'и остаются
валидными, так что тэги, расставленные на v0.1.0, продолжают работать; команды
поиска поменялись на `@tag:[a-z0-9/-]+`.

**Ставится как правила и копируется дословно.** Соглашение поставляется готовыми
файлами правил в [`rules/`](rules/index.ru.md); агент копирует их в целевой
репозиторий как `.claude/rules/llm-wiki-tags/`, и Claude Code подгружает их там
на каждой задаче. Раньше инструкция лишь просила агента написать раздел в
`AGENTS.md` своими словами — теперь во всех репозиториях одна и та же
формулировка. Файлы по языкам (`code-tags-java.md`, `code-tags-python.md`,
`code-tags-golang.md`) несут во front matter глоб `paths:`, поэтому подгружаются,
только когда трогают код на этом языке. В `AGENTS.md` остаётся короткий раздел со
ссылками на правила — для агентов, которые не читают `.claude/rules/`.

**`INSTRUCTIONS.ru.md` перестроен** под это: шаг 1 ставит файлы правил, остальные
шаги их применяют. Страница больше не пересказывает соглашение: формулировкой
владеет `rules/`, а `README.ru.md` описывает её для человека.

**Область применения названа прямо.** llm-wiki-tags — для репозиториев, где
предмет — код, а документация служит его пониманию; сам этот репозиторий состоит
из документации и поэтому своих правил не ставит.

## v0.1.0

Первая опубликованная версия соглашения: llm-wiki (`index.md` в каждой значимой
директории, двусторонние ссылки, у каждой детали одна страница-владелец) **плюс
тэги** — токен `@tag:<slug>`, который ставится *и* в коде, *и* в документации,
так что один `grep` покрывает и то, и другое.

- Формат тэга: YAML front matter в документации (`tags: "@tag:x @tag:y"`),
  комментарий над элементом в коде, четыре уровня (пакет, файл, класс,
  метод/функция).
- Единый реестр тэгов в `docs/tags.md`.
- `INSTRUCTIONS.md` / `INSTRUCTIONS.ru.md` как устанавливаемая полезная нагрузка,
  на которую натравливают агента, и `README.md` / `README.ru.md` как описание для
  человека.
- Правила простановки тэгов для Java, Python и Go в `languages/`.
